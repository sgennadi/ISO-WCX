ISO-WCX v0.21.0 Stable: Image Structure, WIM diagnostics, VS2026 C++26 - Total Commander WCX plugin
================================================================

Installation (no additional tools)
----------------------------------
1. Open https://github.com/sgennadi/ISO-WCX/releases/latest and download
   ISO-WCX-v0.21.0.zip from the published Stable release.
2. Open ISO-WCX-v0.21.0.zip in Total Commander. Confirm the plugin
   installation requested by pluginst.inf.
3. Verify the plugin directory contains ISO-WCX.wcx and ISO-WCX.wcx64.
   These are the 32-bit and 64-bit versions of the same WCX plugin.
4. Restart Total Commander and open an ISO, VHD or VHDX with Ctrl+PgDn.

Preview installation through pluginst.inf (no EXE or helper scripts)
------------------------------------------------------------------
For Total Commander x64 choose ISO-WCX-preview-x64.zip, which contains
only ISO-WCX.wcx64, pluginst.inf and documentation.
For Total Commander Win32 choose ISO-WCX-preview-Win32.zip, which
contains only ISO-WCX.wcx, pluginst.inf and documentation.

From a successful GitHub Actions Preview run, download
ISO-WCX-Installable-x64-Preview or ISO-WCX-Installable-Win32-Preview.
Extract the outer artifact wrapper, then press Enter on the enclosed
ZIP in Total Commander. Confirm the native pluginst.inf installation.
Ctrl+PgDn bypasses the automatic installation prompt.

All 23 unambiguous image extensions are in the native INF
defaultextension list and handled DURING installation. Total Commander
may display a separate association dialog for each one; pluginst.inf
does not support running a post-install command or silently applying all
associations. ZIP/RAR/7z are not listed. The package does not include
scripts or additional EXEs; only one WCX architecture is installed.
If both Total Commander editions exist, choose the ZIP for your edition.

ZIP speed fix in Preview: ISO-WCX no longer advertises the global
PK_CAPS_BY_CONTENT (64) capability, and its probe/OpenArchive reject
ZIP/RAR/7z before scanning an image. Preview capabilities now have
mask 158 rather than Stable v0.21.0 mask 222; TC's normal ZIP support
remains intact. Verify actual ZIP timing after installing this Preview.

No setup EXE, repair CMD, PowerShell script, external parser DLL, virtual
disk mount, driver, or standalone disk extraction program is necessary.
The WCX binaries include ISO/UDF, supported virtual-disk readers and
native ISZ/DAA optical compressed-stream decoding.

Export Image Structure (Stable v0.21.0)
---------------------------------------------------
In Total Commander choose Files > Pack, select an ISO-WCX extension,
click Configure... > Export Image Structure..., choose the source image,
then choose where to save the UTF-8 report (*.txt). The native report
includes the detected filesystem, read-only directory tree and sizes,
attributes, extents, and, for raw ISO/UDF, PVD/Joliet/UDF/El Torito
metadata plus a nonzero system-area warning. Image data is never
copied or modified. No disc_inspect.exe or other utility is required.
The report is saved transactionally and can be shared for diagnosis.
**Stable v0.21.0 includes this button.** Stable v0.20.0 does not.

Updater (introduced in v0.19.0, included in v0.21.0)
------------------------------------------------------------
In Files > Pack select an ISO-WCX extension and click Configure...
to reach Update Settings. Manual Check now always works.
Automatic checks happen at most once daily in the background;
enable "Do not check for updates automatically" to opt out.
The setting is stored per user under HKCU\\Software\\ISO-WCX\\Updates.
When a newer Stable release is found, the updater can download the
official ZIP and SHA256SUMS.txt over HTTPS, verify SHA256 with Windows
BCrypt and offer to open the checked ZIP in Total Commander.
It does not replace the loaded WCX DLL; confirm installation and
restart TC. The prior v0.18.0 Stable release did not contain this
updater. After upgrading, reinstall the WCX association if TC has
cached the older plugin capability flags and Configure... is absent.

Stable v0.20.0 includes bounded Preview FAT12/16/32 editing for fully
allocated fixed VHDX with 512-byte logical sectors. Every write is staged
with CRC32C paired-header and BAT verification and complete independent
logical readback before the physical clone replaces the source. Dynamic,
sparse, differencing, dirty-log and 4K-sector VHDX remain read-only.
Max size: x64 1 GiB logical / 2 GiB physical; Win32 512 MiB each.
See PREVIEW.md and docs/vhdx-native.md for strict limitations.

Preview floppy support: IMA/IMG/VFD/FLP raw images with no partition map
open directly into the FAT12/16/32 root. BIF images open as FAT when valid;
otherwise their original bytes appear as boot-image.bin (read-only).
Stable v0.20.0 includes Preview FAT12/FAT16/FAT32 file and folder
editing for exact-size raw superfloppies and validated FAT `partitionN/`
inside RAW/IMG or fixed VHD. Demand-paged staged writes support source
images up to 64 GiB on x64 (512 MiB Win32). Unicode VFAT creation/replacement/deletion (UTF-8/UTF-16),
checked 8.3 aliases and staged atomic commits are built in. FAT16 fixed
roots and FAT32 FSInfo + mirrored FATs + backup boot sectors are checked.
MBR/GPT FAT volumes can be modified only using the exact path prefix
`partition1/`, `partition2/`, etc. No batch may span two partitions.
Introduced in v0.19.0 Preview, **clean dynamic base VHD v1** can also
be edited at selected FAT12/16/32 partitionN/ paths. It stages a complete
logical disk, checks FAT changes, updates only modified sectors in an
atomic physical VHD clone and independently verifies all logical bytes.
Maximum logical size: 1 GiB (x64) / 512 MiB (Win32). Reserve sufficient
scratch disk space for several copies. Differencing/snapshot VHD, unsupported dynamic/partial/4K-sector VHDX,
oversized or damaged FAT, and opaque BIF remain read-only. This writer
is included as an experimental feature in Stable v0.19.0. The original image and unrelated partitions are never
modified in place; verify adequate free disk space for a full staged clone. Original Stable v0.18.0 had FAT12 writes only. WinImage IMZ is browse/extract-only:
one ZIP stored/deflated floppy image is decompressed in memory with CRC32
validation and a strict 32 MiB image-size limit, without external tools.

The integrated HDD reader supports MBR/GPT partitions containing FAT12/16/32,
exFAT and experimental subsets of ext2/3/4 and NTFS in raw IMG/RAW, fixed
VHD and clean base fixed/dynamic VHDX. Files appear under partition1/, etc.
Modern ext4 optional features and complex NTFS layouts (attribute lists,
compressed/encrypted files, journal recovery) are not supported. Other unsupported virtual
HDD filesystems remain read-only.

Fixing an old broken ISO.WCX association
----------------------------------------
If Total Commander says "File iso.wcx not found!" pointing to an old
...\plugins\wcx\ISO\iso.wcx, it is using the OLD plugin entry.

1. Open Configuration > Options > Packer > Configure packer extension WCXs.
2. Select extension iso and delete ONLY the obsolete mapping to the missing
   ...\ISO\iso.wcx. Do not delete a working unrelated association.
3. Use New type... and choose the installed ISO-WCX\ISO-WCX.wcx.
4. Keep ISO-WCX.wcx64 beside ISO-WCX.wcx for 64-bit Total Commander.
5. Restart Total Commander and retry Ctrl+PgDn.

A DLL cannot change a missing DLL's association before Total Commander
has loaded it. This is a one-time settings correction, not an
additional required program. The leading "192," (legacy) or
"222," (Stable v0.21.0) or "158," (new Preview) in wincmd.ini represents
Total Commander capability flags, NOT part of the DLL path. Never
type these numeric flags in the file selection dialog.

For the Preview build only: if the WCX association dialog's Delete
button does nothing, the package includes optional
ISO-WCX-RemoveAssociation.ps1. Execute it in PowerShell with
-IniPath "C:\\path\\to\\wincmd.ini" -Extension iso for read-only
diagnostics. With Total Commander fully closed, append -Apply to
remove only the ISO-WCX mapping and create an INI backup. The tool
also handles redirected PackerPlugins/PackerPlugins64 sections and
does not modify toolbar buttons or other WCX associations.
ISO-WCX-Repair.ps1 is available for obsolete missing ISO.WCX
references. These scripts are NOT required for normal plugin use.

Check other extensions only if they point to that same obsolete plugin.
The installer also registers `.udf`; a UDF-only `.iso` is detected by content.
The installed plugin also handles cue, ccd, nrg, mds v1, cso, zso,
limited single-file isz/daa, partitioned img, raw, vhd and vhdx.

This is the Stable Core build. Advanced image readers and editing modes
remain experimental, with strict limitations. Most formats are read-only. Plain ISO9660/Joliet,
standard unsplit WIM and restricted UDF Type-1 support editing; ISO/UDF Bridge
supports only byte-only equal-length existing-file replacement.
Supported compressed optical subsets:
single-file ISZ v1 (zero/raw/zlib/bzip2) and DAA 1.00 (raw DEFLATE).
CHD v5 supports compressed optical 2048-byte ISO/UDF and experimental
multi-track CD Mode 1/Mode 2 Form 1 using statically linked libchdr.
MAME four-frame track padding is handled; audio-only and mixed-disc CHDs
expose standard CDDA/trackNN.wav audio at 44.1-kHz stereo/16-bit PCM.
Tracks over the RIFF 4-GiB limit use RF64. CHD remains unassociated by
default because CHD parent chains, exotic CD modes, and other CHD classes
are not fully supported.
Preview: MDS v2/MDF and single-file MDX with encrypted metadata,
unencrypted plain/compressed data tracks, and validated ISO/UDF extraction.
Password-encrypted AES-LRW tracks are deliberately rejected. The preview
installer associates .mdx; external helper executables are not needed.
Not supported: encrypted/multipart ISZ or DAA, DAA 1.10,
CHD parent chains, CD-Text/CD+G, dynamic/differencing VHD,
differencing/dirty VHDX, advanced unsupported ext4 features, NTFS compressed/
encrypted files, attribute-list continuations and journal replay.

Source: https://github.com/sgennadi/ISO-WCX

WIM / ESD
---------
Open WIM, compatible ESD or any member of a complete split SWM set with
Ctrl+PgDn. Browse image1/, image2/, etc. and extract with F5.
Unsplit, non-solid standard WIM supports file/directory edits inside an
existing image index and deletion of an index except the last one.
WIM editing needs NTFS staging and elevated Windows backup/restore/security
privileges. ESD and SWM writes are not supported. Plain ISO9660/Joliet
images support restricted, transactional file/folder edits, including
experimental ISO Long(221) identifiers and Joliet Long(110) UTF-16 units.
Long names can be incompatible with other readers. BIOS/EFI El Torito
sectors are retained and modifications overlapping them are rejected.
ISO/UDF Bridge has limited, byte-only replacement of existing equal-size
files when both filesystems point at one identical physical extent. Bootable
Bridge images, add/delete, resize and UDF metadata edits are refused.
**UDF-only Type-1** (validated nonhybrid single 2048-byte physical
partition): atomic batches of new regular files and nested directories,
bounded replacement/resize, logical FID deletion, multi-ShortAD allocation
including files beyond 4 GiB, safe exclusive-ownership file-block reclaim
and deleted FID slot reuse. Verified bitmap/LVID and staged readback are
required. VAT/Metadata/Sparable partitions, AED chain creation, ISO/UDF
Bridge rebuilding, symlinks/hard links, hybrid system-area and Rock Ridge
rewrites remain unsupported. Important media should be edited as copies. System wimgapi.dll runs inside the WCX;
no additional DLL, EXE, mount or driver is required. NTFS alternate
streams and reparse points are not restored by individual-file extraction.
