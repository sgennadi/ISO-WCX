# Authenticated Stable updates — rollout contract

The current SHA256SUMS.txt downloaded beside the ZIP detects accidental
corruption but **does not authenticate the publisher**. Do not call it signed.

## Proposed v2 format

- Canonical message: exact raw bytes of SHA256SUMS.txt (no newline normalization).
- Signature asset: SHA256SUMS.txt.sig, exactly 64 raw bytes.
- Algorithm: Ed25519, with an independently distributed, pinned public key.
  **Windows BCrypt Ed25519 availability must be established for the minimum
  supported Windows versions**; otherwise choose a Windows-supported ECDSA
  P-256/SHA-256 or RSA-PSS/SHA-256 format and test interop before rollout.
- Require an exact ZIP filename, exactly one digest entry, and a SHA-256 match.
- Signature must be verified before trusting any checksum in the manifest.
- No unsigned fallback when signed-update mode is enabled.
- Bind the requested release tag to the filename and the release metadata;
  reject mismatched names, duplicated digest entries and oversized assets.
- Pin public key bytes in the WCX binary; never fetch the verification key
  from the same GitHub release.
- Keep private signing keys out of the repository, Actions logs and release
  artifacts. Use protected release environments and a dedicated signer.
- Include key ID and a documented revocation/rotation procedure.
- Reject invalid signatures, malformed metadata and unknown key IDs before
  offering installation.
- Test altered ZIP, altered manifest, altered signature, swapped release tags,
  wrong key, truncated signature, and valid signed releases.

## Deployment blocker

No trusted release-signing key has been provisioned. Shipping a hard-coded
example key, a key generated by a CI runner, or an automatically downloaded
public key would create a misleading authenticity guarantee. Until an
independently provisioned key and verifier are integrated and tested, the
updater must describe SHA-256 as an unsigned integrity check only.

Do not publish a Stable release claiming signed updates until the full
contract is implemented and validated on supported Windows versions.
